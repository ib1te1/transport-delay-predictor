# Дашборд «Контур»: диспетчерская транспорта

Дата: 27.09.2026. Область: `web`, без изменения замороженных контрактов.

## Задача и сценарий

Диспетчер видит положение транспорта, выделяет транспорт с риском отклонения,
открывает прогноз на целевую остановку в горизонте 10–15 минут, сверяет причины
модели с последними остановками и фактическим треком. Основание кейса —
`case-brief.md`; оформление и взаимодействие ниже являются решениями проекта.

## Визуальная концепция

«Контур» — спокойная рабочая поверхность: тёмно-синяя верхняя панель,
светлый нейтральный фон, белые панели, бирюзовый акцент навигации.
Красный, охра и зелёный зарезервированы для риска. Системный шрифт без
внешней загрузки, табличные цифры, иерархия заголовков, тонкие разделители.
Содержимое плотное, но основные действия имеют площадку не менее 36 px.

Верхняя панель содержит название, статус соединения и часы **данных** в UTC.
Под заголовком — фильтры-счётчики: все ТС, высокий риск, отклонение,
в пределах нормы, без прогноза. Счётчики описывают весь снимок, число
результатов поиска подписано отдельно. Нет выдуманных маршрутов, KPI,
«эффективности», процентов точности или демонстрационных данных в приложении.
При открытых предупреждениях рядом с номером снимка показывается их количество;
нажатие открывает соответствующее ТС.

Основная область: слева поиск и приоритетный список, в центре карта,
справа карточка выбранного ТС. До выбора справа объясняется сценарий и
показывается качество доступных данных. На узких экранах блоки выстраиваются
вертикально; выбор переводит фокус к карточке. Нет неработающих пунктов меню.

Карта расширяет охват по мере появления новых ТС и не перебивает ручное
масштабирование или перемещение. Кнопка возвращает видимый парк либо
выбранное ТС. При выборе карта охватывает его положение, плановую линию и
недавний фактический трек; пока диспетчер не перемещал карту вручную, ТС
остаётся в кадре. Отдельный слой сети строится по `/api/stops`: остановки каждого
рейса соединяются по `stop_order`, с разрывом при паузе расписания от семи
минут. `route_id` в этом ответе равен `tr_id`:
в исходном расписании нет публичного номера маршрута. Линия показывает
последовательность плановых остановок, а не дорожную геометрию. Фактический
трек ТС отображается отдельно. Отрезки трека дальше трёх километров от всех
его плановых остановок помечаются жёлтым пунктиром, рядом указывается
расстояние от текущей позиции до ближайшей остановки. При паузе телеметрии
более двух минут линия разрывается: путь в этот период неизвестен.
GPS-координаты не переносятся на линию плана.
ТС без координат остаются в списке, карта явно сообщает их количество.
Кнопки маркеров и дублирующий список доступны с клавиатуры.

## Семантика данных

- Идентификатор: `ТС {tr_id}`. Номер маршрута неизвестен.
- Риск берётся только из `prediction.risk_level`, пороги не повторяются.
  Yellow означает «Отклонение», в том числе движение раньше расписания.
- Отрицательный прогноз — опережение, положительный — задержка.
- `p_late` — вероятность опоздания более чем на 120 секунд, не уверенность
  модели; `null` отображается как отсутствие оценки.
- Прогноз относится к **целевой**, не обязательно следующей остановке.
- `degraded` и причина резервного расчёта видны отдельно от риска.
- `freshness` не пересчитывается браузером. Offline — серый маркер;
  отсутствие прогноза — нейтральная маркировка.
- Время снимка, телеметрии и прогнозов показывается в UTC, независимо от
  времени компьютера. Потеря соединения не скрывает последнее состояние.
- Живой MAE при `null` — «Ещё нет проверок», а не ноль. Алерты пока
  не реализованы бэкендом; интерфейс показывает прогнозы, не журнал инцидентов.

## Интеграция

Источник: `VITE_API_URL` (существующая переменная compose). При её отсутствии
используется тот же hostname и порт 8000. HTTP(S) определяет WS(S).
Используются `/api/state`, `/api/vehicles/{tr_id}`, `/api/stops`, `/ws`.
Типы соответствуют `services/api/app/schemas.py`, пакет contracts не меняется.

Клиент сначала открывает WebSocket и буферизует события, затем берёт снимок.
Отбрасывает события `seq <= snapshot.seq`, применяет остальные последовательно.
Пропуск seq вызывает повторный снимок; переподключение всегда начинает новый
сеанс со снимком, поскольку после рестарта API seq сбрасывается. Буфер ограничен,
зависшие HTTP-запросы отменяются по таймауту. Разрыв связи — повтор с увеличением
паузы. Открытый WS без сообщений получает отдельный статус задержки потока.

`vehicles` изменяет парк, включая удаление; `prediction` обновляет только
историю карточки (не карту), `clock` — часы, `alert` — список из снимка.
Сводка пересчитывается по текущим VehicleView после диффов. Карточка
перезапрашивается после восстановления и периодически для трека и остановок;
параллельный поздний ответ прежнего выбора не заменяет новый. Во время запроса
буферизуются события prediction; после ответа применяются только seq выше
card.seq, история без дублей sample_id и в порядке от нового к старому.

## Доступность и отказоустойчивость

Семантические заголовки, подписанные поля, видимый focus, кнопки вместо
кликабельных div, цвет дополнен текстом; отдельный status для связи.
Учитывается prefers-reduced-motion. Ошибки карты не блокируют список/карточку.
Состояния: загрузка, пустой парк, нет результатов, нет координат,
недоступный API, потеря/задержка потока, 404/503 карточки, резервный прогноз.

Подложка — стандартные растровые тайлы OpenStreetMap с видимой атрибуцией.
Она включается только после явного нажатия «Подложка»; это сохраняет
работоспособность офлайн и не делает внешние запросы обязательными.
По умолчанию координаты и трек показаны на нейтральном координатном поле.
Нет скачивания регионов и предзагрузки; стандартный browser cache и Referer.
При ошибке тайлов отображается пояснение и доступно выключение подложки.

## Приёмка

Node 24: строгая проверка TypeScript, production build, тесты протокола
(snapshot/buffer, дубликаты, gap, reset), сводки, отрицательных прогнозов и
истории карточки. Сквозной тест проверяет доступность модулей клиента через
Vite и реальные API-ответы. Ручная проверка: desktop/mobile, клавиатура,
поиск/фильтры, выбор ТС, пустое состояние, недоступный backend/подложка.
